## 三、评论清洗逻辑（实现细节 + 代码）

### 3.1 处理流程
1. **规范化**：去 HTML、压缩空白、标准化 rating/date/version  
2. **过滤**：无有效 id、空内容、过短/纯符号低信号评论剔除  
3. **去重**：按 review id；再按 content hash 去内容重复  
4. **报告**：输入/输出数量、各类剔除数、评分直方图、版本 TopN

## 四、Findings 生成机制（实现细节 + 代码）

### 4.1 机制说明（非关键词表）
1. **确定性统计先行**：评分直方图、低分率、Top 版本（`origin=stat`）  
2. **压缩评论后送模型**：限制条数与字段长度，附带 analysis_goal  
3. **Prompt 约束**：禁止编造 review ID；必须动态发现主题；返回 JSON  
4. **后端证据校验**：`evidence_review_ids` 必须属于 cleaned reviews；否则整条 finding 拒绝  
5. **区分来源**：模型结论 `origin=model`；统计独立存放 `analysis_stats`  

### 4.2 Prompt 规则摘要（`prompts/findings.py`）

```text
- Only use provided reviews. Never invent review IDs or quotes.
- Findings must be dynamic topics, NOT a fixed keyword taxonomy.
- Every finding MUST include evidence_review_ids that exist in the input.
- Return ONLY valid JSON. Escape quotes.
```

### 4.3 证据校验关键代码（`analyze.py`）

```python
by_id = {str(r.get("id")): r for r in reviews}
valid_ids = []
for rid in evidence_ids:
    rid_s = str(rid)
    if rid_s in by_id and rid_s not in valid_ids:
        valid_ids.append(rid_s)

if not valid_ids:
    rejected.append({
        "reason": "no_valid_evidence_review_ids",
        "title": item.get("title"),
        "claimed_ids": evidence_ids,
    })
    continue

# support_count 以校验后的 valid_ids 为准重算
```

## 五、LLM 调用、数据隐私与错误处理

### 5.1 LLM 调用方式
| 项 | 配置 |
|----|------|
| Provider | Moonshot（OpenAI 兼容） |
| 默认模型 | `moonshot-v1-32k`（可用环境变量覆盖） |
| 调用点 | analyze / plan / testcases |
| 温度 | 约 0.1（偏稳健） |
| 输出约束 | `response_format=json_object` + 修复重试 |
| 密钥 | 仅 `backend/.env` 的 `MOONSHOT_API_KEY`，**不入库** |

关键调用逻辑（`moonshot_client.py`）：

```python
payload = {
    "model": self.model,
    "messages": messages,
    "temperature": temperature,
}
if force_json:
    payload["response_format"] = {"type": "json_object"}

# 429：sleep ~22s 后重试一次
# 非法 JSON：追加 repair 消息重试（chat_json）
```

流水线在 analyze→plan、plan→testcases 之间 **sleep(22)**，降低组织 RPM 触发概率。

### 5.2 数据隐私
- 不采集用户设备通讯录/相册等隐私；仅处理公开 App Store 评论或用户导入文件  
- API Key 不写进仓库；README 明确禁止提交密钥  
- 导入数据仅本地处理，不上传到第三方（除调用 Moonshot 时发送**压缩后的评论文本**用于分析）  
- 发送给模型的内容：截断后的 title/content + 统计摘要 + goal；不含 `.env`  

### 5.3 错误处理

| 场景 | 处理 |
|------|------|
| 缺 API Key | 抛 `MoonshotError`，Job failed，stage=error，message 明确 |
| 非法 App URL | `InvalidAppUrlError`，任务失败 |
| 采集失败/空 | CollectError 或 limitations 透明记录 |
| 模型坏 JSON | 修复重试；plan/testcases 可规则 fallback |
| HTTP 429 | 退避重试；仍失败则 fallback（用例） |
| 幻觉 ID | 校验拒绝，不进入 artifacts 正式列表 |
| 断链 | validate 输出 issues；ok=false |

Fallback 时 artifacts 仍含 `planning_notes` / `testing_notes` / `*_error`，可审计。
