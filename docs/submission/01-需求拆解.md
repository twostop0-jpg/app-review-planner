# 阶段1 需求拆解清单

项目：App Review Planner（美区 App Store 评论 → Findings → PRD → 测试用例）  
仓库：https://github.com/twostop0-jpg/app-review-planner

## 1. 背景目标
输入美区 App Store 链接与可选分析目标，自动完成评论采集、清洗、问题发现、版本化 PRD、测试用例生成与追溯校验，并通过可运行 UI 展示进度与结果。

## 2. 功能点清单（含输入/输出/验收口径）

| ID | 功能点 | 输入 | 输出 | 验收口径 |
|----|--------|------|------|----------|
| F1 | 分析范围设定 | App URL、goal、source | scope（app_id/focus/storefront） | 正确解析 app_id；storefront=us；记录用户目标 |
| F2 | 评论采集 | live/sample/import | reviews_raw、collection_meta | 美区数据或明确标注缓存/导入；不伪造评论；记录 limitations |
| F3 | 评论清洗 | reviews_raw | reviews_cleaned、cleaning_report | 规范化、去重、统计完整；本阶段不调用 LLM |
| F4 | 动态 Findings | cleaned + goal | findings、analysis_stats | 非固定关键词表；每条含证据 review ID；无效证据剔除 |
| F5 | PRD/版本规划 | findings + goal | prd（requirements、version_plan） | 需求关联 finding/review；含 P0/P1/P2 与版本拆分 |
| F6 | 测试用例生成 | PRD requirements | testcases | 用例关联 req_id 与 review_id；含步骤与期望结果 |
| F7 | 追溯校验 | reviews/findings/prd/testcases | validation | 校验评论→发现→需求→用例；ok=true 或列出 issues |
| F8 | 任务编排与进度 | 创建 Job | stages 状态机 | 可轮询；失败时标记 error stage 与 error 信息 |
| F9 | 产品 UI | 用户操作 | 结构化结果页 | 支持 sample/live/import；展示 findings/PRD/用例/追溯 |
| F10 | 导入兼容 | JSON/CSV | 进入同一流水线 | 字段文档化；未见过数据可跑通 |

## 3. 约束
- 必须使用美区评论；不硬编码某 App 专属结论
- 密钥仅通过环境变量配置，不入库
- 数据不足时透明说明，不编造评论

## 4. 阶段验收标准（对本阶段文档）
- 功能点覆盖采集→分析→规划→用例→追溯→UI
- 每项有明确输入、输出、可执行验收口径
- 可据此进入技术方案设计
