# 各阶段学习成果说明

> 可直接复制到平台「提交成果」的说明栏，或随对应阶段文档一并上传。  
> 项目：App Review Planner  
> 仓库：https://github.com/twostop0-jpg/app-review-planner

---

## 阶段1 需求拆解 — 学习成果说明

本阶段完成了 App Review Planner 的需求拆解，明确了从「美区 App Store 链接 + 分析目标」到「Findings / PRD / 测试用例 / 追溯校验」的产品目标。

**成果内容：**
- 输出功能点清单（F1–F10），覆盖采集、清洗、分析、规划、用例、追溯、UI、导入兼容
- 每个功能点写清输入、输出与可执行验收口径
- 明确约束：美区数据、不硬编码结论、不伪造评论、密钥不入库

**对应材料：** `docs/submission/01-需求拆解.md`  
**收获：** 学会把业务场景拆成可验收的功能点，而不是只写模糊需求描述。

---

## 阶段2 技术方案草图 — 学习成果说明

本阶段基于需求拆解，完成了技术方案设计，理清模块边界与关键流程。

**成果内容：**
- 划分 UI、API、Pipeline、collect/clean、模型阶段、validate、Moonshot 客户端等模块边界
- 给出架构草图与 Job 异步流水线关键流程说明
- 说明规则 vs 模型的技术取舍
- 识别网络、限流、幻觉、端口等风险及应对策略

**对应材料：** `docs/submission/02-技术方案草图.md`  
**收获：** 学会在实现前先定边界与风险，避免一上来堆代码导致难联调。

---

## 阶段3 数据与接口定义 — 学习成果说明

本阶段完成了核心数据结构与 HTTP 接口定义，保证前后端与流水线各阶段可协作。

**成果内容：**
- 定义 Review / Finding / Requirement / TestCase / Job / Stage 字段与约束
- 定义 `/api/jobs`、`/api/jobs/{id}`、preview 等接口的请求响应与异常路径
- 约定追溯链：评论 → 发现 → 需求 → 用例

**对应材料：** `docs/submission/03-数据与接口定义.md`  
**收获：** 学会用字段约束和接口契约支撑多阶段流水线，减少联调歧义。

---

## 阶段4 核心功能实现 — 学习成果说明

本阶段完成了核心功能落地与本地自测，形成可运行的分析流水线与产品页。

**成果内容：**
- 实现七阶段 Pipeline：scope → collect → clean → analyze → plan → testcases → validate
- 用 Moonshot 完成 Findings / PRD / 测试用例生成，并用后端校验证据链接
- 提供 FastAPI 托管的中文产品 UI（无需 Node）
- 记录自测用例与通过情况

**对应材料：** `docs/submission/04-核心功能实现.md`  
**收获：** 学会把 Prompt + 工具链 + 校验闭环做成可演示的 Agent/流水线原型。

---

## 阶段5 联调与问题修复 — 学习成果说明

本阶段完成了模块联调，并针对真实问题完成定位与修复。

**成果内容：**
- 记录 UI↔API↔Pipeline↔Moonshot 的联调结果
- 整理问题清单（端口占用、Swagger 默认参数、模型坏 JSON、429 限流、Git 推送、无 Node 等）
- 说明修复方案：JSON 硬化与 fallback、429 退避与阶段间隔、Python UI、代理推送等

**对应材料：** `docs/submission/05-联调与问题修复.md`  
**收获：** 学会用问题清单管理缺陷，并把联调中的不稳定因素（限流/网络）做成可恢复设计。

---
