# 阶段3 数据与接口定义

项目：App Review Planner  
仓库：https://github.com/twostop0-jpg/app-review-planner  
代码依据：`backend/app/models/schemas.py`、`backend/app/api/routes.py`

## 1. 核心数据结构

### 1.1 Review
| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | string | 必填 | 评论唯一 ID |
| app_id | string | 必填 | App ID |
| rating | int\|null | 1–5 或空 | 评分 |
| title/content/author | string | 可空 | 文本 |
| date/version | string\|null | 可空 | 日期/版本 |
| country | string | 默认 us | 美区 |
| source | live\|sample\|import | 枚举 | 来源 |

### 1.2 Finding
| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| finding_id | string | 必填 | 如 f1 |
| title/summary | string | 必填/可空 | 标题摘要 |
| severity | high\|medium\|low | 枚举 | 严重度 |
| evidence_review_ids | string[] | 校验后非空 | 必须存在于 cleaned |
| support_count/confidence | number | >=0 / 0–1 | 支持与置信 |
| assumption | bool | 默认 false | 弱证据标记 |
| origin | model\|stat\|rule | 枚举 | 来源 |

### 1.3 Requirement
| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| req_id | string | 必填 | 如 R1 |
| priority | P0\|P1\|P2 | 枚举 | 优先级 |
| version | vNext-1\|vNext-2\|Research | 枚举 | 版本桶 |
| linked_finding_ids | string[] | 必填有效 | 关联发现 |
| linked_review_ids | string[] | 必填有效 | 关联评论 |
| acceptance_criteria | string[] | 建议非空 | 验收标准 |

### 1.4 TestCase
| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| tc_id | string | 必填 | 如 TC1 |
| steps | string[] | 建议非空 | 步骤 |
| expected_result | string | 建议非空 | 期望 |
| linked_req_ids | string[] | 必填有效 | 关联需求 |
| linked_review_ids | string[] | 必填有效 | 须属于关联需求 |
| origin | model\|rule | 枚举 | 生成来源 |

### 1.5 Job / Stage
- JobStatus：`queued|running|succeeded|failed`
- StageStatus：`pending|running|done|error|skipped`
- artifacts：字典，含 reviews、findings、prd、testcases、validation 等

## 2. 接口定义

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/` | 产品 UI |
| GET | `/health` | 健康检查，返回 `{status:ok}` |
| POST | `/api/jobs` | 创建分析任务 |
| GET | `/api/jobs/{job_id}` | 查询状态与产物 |
| POST | `/api/collect/preview` | 采集预览 |
| POST | `/api/clean/preview` | 清洗预览 |

### 2.1 POST /api/jobs
请求：
```json
{
  "app_url": "https://apps.apple.com/us/app/id839285684",
  "goal": "improve retention and billing clarity",
  "source": "sample",
  "import_path": null,
  "max_pages": 5
}
```
响应：`{"job_id":"..."}`

异常：URL 非法、采集失败、模型关键错误 → Job `failed`，`error` 有信息；对应 stage=`error`。

### 2.2 GET /api/jobs/{job_id}
响应核心字段：`status`、`stages[]`、`artifacts`、`error`  
404：job 不存在。

## 3. 字段约束与异常路径
- source=import 时必须提供可解析的 import_path
- finding/requirement/testcase 的外键 ID 不存在则拒绝该项
- Moonshot 超时/429/坏 JSON：重试；最终可 fallback；仍无有效产物则阶段失败
- live 无数据：记录 limitations 或任务失败，不编造

## 4. 追溯协议
```text
Review.id → Finding.evidence_review_ids
         → Requirement.linked_* 
         → TestCase.linked_*
```
